# NEXUS — Personal Digital Universe
## 完整项目开发总提示词

你是一名资深全栈工程师、Three.js/WebGL 图形开发工程师、React 架构师和高级 UI/UX 设计师。

请协助我从零开发一个名为 **NEXUS — Personal Digital Universe（个人数字宇宙）** 的独立网站。

这不是普通的网站导航页面，而是一个将我个人名下所有网站、博客、个人项目、在线工具和社交主页统一连接起来的 3D 数字宇宙。

项目的核心理念：

**把我的个人数字资产组织成一个可以探索、交互、管理和访问的三维网络空间。**

---

# 一、产品定位

产品名称：NEXUS

产品类型：
- 个人数字宇宙
- 3D 网站导航系统
- 个人数字资产控制中心

核心功能：
1. 将所有个人网站统一展示在一个 3D 空间中。
2. 不同类型的网站组织成不同的星系。
3. 每个网站表现为一个可交互的 3D 节点。
4. 网站之间可以建立可视化连接关系。
5. 点击网站节点可以查看详细信息。
6. 用户可以通过按钮打开对应的真实网站。
7. 提供独立的网站列表和搜索界面。
8. 提供控制中心，用于管理网站、分类和关联关系。

产品只面向个人使用。

第一版不需要：
- 用户注册和登录
- 多人协作
- 云端数据库
- 网站在线状态监测
- 自动爬取网站内容
- 网站流量分析
- 复杂的后端服务

第一版以手动维护网站配置为主，使用 JSON 保存网站数据。

---

# 二、视觉设计要求

整体视觉方向：

**Cyberpunk + Sci-Fi + GPU Particle Universe**

参考视觉：
- 科幻电影中的全息控制中心
- 未来数字宇宙
- 3D 数据网络
- 量子粒子场
- 赛博朋克科技界面
- GPU 粒子模拟效果

配色：
- 背景：#050812
- 主色：#00D9FF
- 辅助色：#8B5CF6
- 强调色：#00FFA3
- 普通文字：浅灰白色

视觉要求：

1. 使用深色空间背景。
2. 具有真实空间纵深感。
3. 具有三维星系和网站节点。
4. 网站节点使用发光球体或全息图标。
5. 节点之间使用动态光线连接。
6. 背景可以使用星尘、微弱粒子和网格。
7. 重要节点可以拥有独特的光环。
8. UI 使用半透明玻璃面板。
9. 使用柔和的光晕和过渡动画。
10. 不要让所有元素都发光，保持视觉层次。

整体效果必须精致、克制、有空间感，不能做成廉价的游戏 HUD 或普通后台管理系统。

# 四、网站页面

## 1. Universe — 三维数字宇宙

这是整个产品最重要的页面。

打开网站后，默认进入 Universe。

场景要求：

- 深色三维空间。
- 星空粒子背景。
- 中央个人核心节点。
- 周围分布不同网站分类的星系。
- 星系中包含网站节点。
- 网站之间可以有关系连线。
- 粒子沿部分连接线流动。
- 节点具有柔和发光效果。
- 选中节点时产生明显的视觉反馈。

交互要求：

- 鼠标拖动可以旋转空间。
- 滚轮可以缩放。
- 点击节点可以选中节点。
- 双击节点可以打开网站。
- 点击分类可以聚焦对应星系。
- 点击重置按钮恢复默认视角。
- 点击搜索结果后摄像机自动定位到目标节点。

需要避免：
- 节点随机剧烈移动。
- 摄像机控制过于灵敏。
- 粒子过多导致卡顿。
- 页面初次加载出现长时间空白。
- 节点和 UI 面板互相遮挡。

节点应有稳定、可预测的空间位置。

## 2. Explorer — 网站探索器

提供普通列表视图。

功能：
- 展示所有网站。
- 网站搜索。
- 分类筛选。
- 标签筛选。
- 收藏。
- 最近访问。
- 点击查看网站详情。
- 打开真实网站。

该页面必须在没有 3D 场景的情况下独立使用。

## 3. Control Center — 控制中心

用于管理个人数字资产。

功能：
- 新增网站。
- 编辑网站。
- 删除网站。
- 新增分类。
- 编辑分类。
- 删除分类。
- 创建网站关联关系。
- 编辑网站关联关系。
- 修改节点空间坐标。
- 设置网站是否在宇宙中显示。
- 设置网站是否为重点节点。

所有数据变化都应及时反映到 Universe 和 Explorer。

## 4. About — 个人数字身份

展示：
- 个人简介。
- 技术方向。
- 个人项目。
- 个人网站。
- 社交主页。
- 联系方式。

# 五、3D 空间设计

采用分层空间布局。

## 核心节点

代表个人身份，是整个数字宇宙的中心。

## 星系

每个星系代表一个网站分类。

初始分类可以包括：

- Developer
- Projects
- Knowledge
- Social
- Tools
- Other

分类可以由用户修改。

## 网站节点

每个网站是一个独立节点。

节点需要支持：
- 悬停。
- 点击。
- 选中。
- 详情展示。
- 打开网站。
- 摄像机定位。

节点可以使用不同图标和颜色区分网站类别。

## 连接关系

网站之间可以建立关联关系。

关系类型：
- belongs-to
- related-to
- built-with

连接关系应来自 JSON 数据，而不是随机生成。

连接线可以具有流动粒子效果。

# 八、性能与兼容性

1. 3D 场景必须使用合理的渲染策略。
2. 尽量复用几何体和材质。
3. 使用 InstancedMesh 或其他合适技术管理大量相似节点。
4. 避免在每一帧创建大量对象。
5. 合理限制粒子数量。
6. 避免无意义的 React 高频状态更新。
7. 在页面不可见时暂停或降低动画更新。
8. 对低性能设备提供低画质模式。
9. 对 WebGPU 不支持的设备提供兼容方案。
10. 3D 加载失败时仍然可以使用 Explorer。
11. 支持移动端基本访问。
12. 尊重 prefers-reduced-motion 设置。

不要为了追求视觉效果牺牲基本可用性。

---

# 九、外部网站安全

1. 网站 URL 必须通过 URL 格式校验。
2. 只允许 http 和 https 协议。
3. 打开外部链接时使用 target="_blank"。
4. 配合 rel="noopener noreferrer"。
5. 对无效网址提供明确提示。
6. 不允许用户通过网址字段执行 javascript: 等危险协议。
